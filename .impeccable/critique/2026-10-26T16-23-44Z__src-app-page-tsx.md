## 우선 개선 사항

1. **P1: 기존 모임보다 생성 CTA가 더 강하다.** HomeLayout.tsx:45–58, HomeActions.tsx:41–49. 데스크톱의 큰 코랄 생성 카드와 우측 작은 모임 목록이 경쟁한다. 모임 한 개 아래 우측은 비고 안내가 왼쪽으로 길어진다. 내 모임·재진입을 첫 우선순위로 하고 생성·참여는 보조 동작으로 배치한다. 제안: impeccable layout / distill.
2. **P1: 데모가 긴 설명 뒤에 묻힌다.** HomeGuide.tsx:15–19,47–65. 390px에서 데모 링크의 문서상 시작점이 약1193px이다. 네 단계와 네 결정 방식 설명에 앞서 실제 체험을 발견하게 한다. 제안: impeccable onboard / distill.
3. **P2: 320px에서 읽기·입력 배치가 약해진다.** HomeGuide.tsx:47–65, HomeActions.tsx:58–79. 데모 링크 폭232.8px·높이185.3px에서 아바타와 화살표 때문에 설명이 짧은 단위로 쌓인다. 입력 폭127.9px에서는 placeholder가 잘린다. 좁은 화면에서 아바타·설명 행을 분리하고 입력과 버튼을 재배치한다. 제안: impeccable adapt.
4. **P2: 제품의 실제 사용 장면보다 절차 설명이 많다.** page.tsx:18–24, HomeGuide.tsx:15–19. 의견·후보·완성 일정의 작동 사례를 데모나 작은 예시로 전달하면 이해가 빠르다. PRODUCT.md의 일부 조건·충돌 설명은 현재 홈의 의견 투표 흐름과 다르므로 구현을 확인하지 않은 기능을 홍보하거나 시안에 추가하지 않는다. 제안: impeccable clarify / onboard.
5. **P2: 입력 안내와 예외 상태의 완성도가 부족하다.** HomeActions.tsx:55–70의 실제 label은 '초대받았나요?'이고 6자리 조건은 오류 후 나타난다. 입력 형식을 상시 안내한다. Button.tsx:19의 sm은36px로 MyRooms의 모두 보기·재시도에 적용되므로 프로젝트 권장44px로 보강한다. useAccount.ts:29–32 및 ProfileMenu.tsx:44는 요청 실패 시 account=null/빈 공간으로 끝나 재시도·설명을 제공하지 않는다. 소스에서 확인했고 해당 실패는 재현하지 않았다. 제안: impeccable clarify / adapt / harden.
